# IntMusic 使用手册

本文面向安装、使用和维护 IntMusic 的用户。开发者可继续阅读 [总体架构](architecture.md) 和 [发布说明](../packaging/README.md)。

## 1. 开始之前

### 1.1 选择 Core 设备

一个 IntMusic 系统至少需要一台长期运行的 Core。建议选择：

- 存放主要音乐库的 Windows、macOS 或 Linux 设备。
- 在家庭局域网中地址相对稳定、不会频繁休眠的设备。
- 具有足够磁盘空间保存数据库、封面缓存、转码缓存和可能的分发中继文件。

其他电脑和 Android 设备只安装 Client 即可。Client 也可以持有自己的音乐文件，不要求 Core 拥有全部音频。

### 1.2 备份

IntMusic 不替代原始音乐备份。至少保留：

- 音乐文件的独立备份。
- Core 的 `library.sqlite3` 定期备份。
- Android 正式签名 keystore、密码和别名的离线备份。

Client 缓存和离线投影可以重新生成，一般不需要作为唯一备份保存。

## 2. 安装

### 2.1 Windows

运行 `IntMusic-Windows-Setup.exe`，根据用途选择：

- **仅客户端**：连接其他设备上的 Core。
- **仅 Core**：将当前电脑作为无界面服务器。
- **Core + 客户端**：家庭中第一台设备的推荐选项。

Core 会注册为 Windows 服务 `IntMusicCore` 并开机启动。安装器还会创建局域网所需的防火墙规则。

安装或升级前，安装器会请求 Client 正常退出并停止 Core 服务。若升级失败，可在管理员 PowerShell 中检查：

```powershell
Get-Service IntMusicCore
Get-Content C:\ProgramData\IntMusic\Core\install.log -Tail 100
Get-Content C:\ProgramData\IntMusic\Core\service.log -Tail 100
```

### 2.2 macOS

解压发布包并把 `IntMusic.app` 移入“应用程序”。正式发布包应使用 Developer ID 签名并完成公证；未签名的开发构建可能需要在“系统设置 → 隐私与安全性”中手动允许。

macOS Client 可以连接其他 Core，也可以通过命令行在当前 Mac 运行 Core：

```bash
cargo run -p core-cli -- serve
```

开发构建和正式分发的签名方式见 [发布说明](../packaging/README.md)。

### 2.3 Android

安装 release APK。后续版本必须使用同一个 keystore 签名，才能覆盖升级而不丢失应用数据。签名不同的 APK 只能先卸载旧版本再安装。

Android 首次运行时按需要授予：

- 音乐和音频读取权限。
- 通知权限，用于媒体播放通知。
- 后台播放相关权限。
- 通过系统目录选择器授予的文件夹持久访问权限。

在 HarmonyOS 的 Android 兼容环境中，可见路径不一定等于可授权路径。应始终从 IntMusic 的“添加本地文件夹”调用系统选择器，不建议手工填写 `/storage/emulated/0/...`。

### 2.4 Linux

使用对应发行产物运行 Flutter Client 和 Core。服务端可参考 `packaging/linux-systemd` 配置 systemd。音频输出能力取决于构建时启用的后端和系统音频服务。

## 3. 首次连接 Core

1. 确认 Core 已启动。
2. 打开 Client 的“设置 → 核心服务”。
3. 优先点击“发现”。Client 会搜索 `_intmusic-core._tcp.local.` 并检查 `49330–49360` 端口。
4. 发现失败时手动填写地址，例如 `http://192.168.50.153:49342`。
5. 点击“连接”，等待状态区域显示 Core 名称、版本、API 和数据库路径。

同一台设备上的 Client 应使用实际运行端口，例如 `http://127.0.0.1:49342`，而不是假设端口永远是 49330。

### 3.1 连接失败

按顺序检查：

1. Core 服务是否运行。
2. Client 地址中的 IP 和端口是否正确。
3. 浏览器能否打开 `http://地址:端口/api/v1/status`。
4. Windows 网络是否设为“专用网络”。
5. 防火墙是否允许 TCP `49330–49360` 和 UDP `5353`。
6. VPN、Tailscale 或公司网络是否阻断 mDNS；这种情况下可直接填写 IP。

其他 Client 离线不会导致本机 Client 无法连接 Core。连接故障只与 Core 进程、地址、端口、防火墙和当前网络路径有关。

## 4. 添加音乐

IntMusic 有两种音乐来源，选择前先确认文件实际位于哪台设备。

### 4.1 Core 音乐文件夹

适用于 Core 所在设备能够直接访问的路径。

1. 打开“设置 → 音乐文件夹”。
2. 输入或选择 Core 设备上的路径。
3. 添加后点击“重新扫描音乐库”。
4. 在资料库管理中观察文件数、容量和问题数。

Client 位于另一台电脑时，不要在这里填写该 Client 的本地路径；Core 无法访问那条路径。

### 4.2 此设备上的音乐

适用于文件只保存在当前 Client：

1. 打开“设置 → 此设备上的音乐”。
2. 点击“添加本地文件夹”。
3. 使用系统目录选择器授权路径。
4. 点击单个来源旁的同步按钮，或使用“同步全部”。

Client 会读取文件的内嵌标签并把元数据、媒体参数、相对路径和指纹发送给 Core。音频文件不会因为扫描而上传。

### 4.3 标签识别规则

IntMusic 只把文件内嵌标签或用户手动录入的信息作为权威资料，不使用文件名、父目录和目录层级推断标题或艺术家。

至少缺少标题或主要艺术家的文件会进入“资料库管理 → 待处理”。可以：

- 手动补录资料。
- 将文件关联到已有歌曲。
- 忽略不需要进入资料库的文件。
- 修复文件标签后请求重新扫描。

## 5. 浏览与搜索

侧边栏或紧凑导航提供首页、专辑、艺术家、歌曲、歌单、播放、历史、资料库管理和设置。

- 使用页面右上角切换列表/画廊视图。
- 使用排序按钮选择标题、名称或其他可用字段。
- 页面内筛选只影响当前类别。
- 顶部全局搜索同时查找歌曲、专辑、艺术家和歌单。
- 点击艺术家名、专辑名和资料标签可以继续跳转。
- 使用前进/后退按钮返回时，列表应恢复之前的滚动位置。

离线时搜索与浏览读取本地投影。首次安装后若从未完成一次在线同步，离线目录可能不完整。

## 6. 播放音乐

### 6.1 选择播放区域

1. 打开“播放”或底部播放器的设备按钮。
2. 在设备分组中选择目标 zone。
3. 点击歌曲、专辑或歌单的播放按钮。

一个 Client 可以暴露多个系统音频输出。若平台只允许控制默认输出，界面会标记能力限制。

设置中可以：

- 将当前 Client 区域置顶。
- 按名称排序。
- 让正在播放的区域排在空闲区域之前。

### 6.2 播放集合

- “播放”按当前列表顺序替换队列并从所选歌曲开始。
- “随机播放”创建稳定的随机顺序。
- “下一首播放”插入当前项之后。
- “添加到队列”追加到队尾。

从收藏、歌单、专辑或搜索结果播放时，队列应来自当时可见的集合，而不是随机抽取整个资料库。

### 6.3 播放模式

在底部栏、播放页面或待播放列表中切换：

- 顺序播放。
- 随机播放。
- 单曲循环。
- 列表循环。

模式属于当前播放会话。远程 Client 与 renderer 应显示相同状态；离线时本机继续使用已保存的会话模式。

### 6.4 音量

点击音量按钮会同时显示：

- **播放器音量**：只改变 IntMusic 当前 zone 的软件音量。
- **系统音量**：改变 renderer 当前音频输出端点的系统音量。

默认输出的系统音量通常对应系统当前默认设备；选择明确的非默认端点时，应控制该端点，而不是无条件修改全局默认设备。平台不支持时系统滑块会禁用或标注不可用。

## 7. 队列与播放页面

打开待播放列表时，界面会定位到当前歌曲。可以移动、移除或选择队列项。关闭再打开不应回到队首。

播放页面包含：

- 封面、标题、艺术家、专辑和收藏。
- 进度、上一首、播放/暂停、下一首和模式。
- 设备、音量、详情和队列入口。
- 歌词、翻译、注音和演唱者显示。

桌面宽屏使用封面/歌词双栏；较窄窗口和 Android 使用单栏或分页面板，并保留过渡动画。

## 8. 歌单

### 8.1 普通歌单

在“歌单”页面新建歌单。通过歌曲更多菜单或批量选择加入歌单。普通歌单保留显式顺序。

### 8.2 智能歌单

新建或编辑智能歌单时添加规则：

1. 选择字段，例如艺术家、专辑、年份、收藏、格式或歌曲来源。
2. 选择比较方式。
3. 从候选中选择值。
4. 选择满足全部条件或任一条件。

歌曲来源规则直接提供已知设备/来源选项，不需要输入内部 ID。

## 9. 编辑歌曲、专辑和艺术家

### 9.1 歌曲

在歌曲详情点击“编辑”。可修改标题、参与人员、专辑位置、日期、流派、评分和歌词。默认编辑 IntMusic 的资料，不会自动写回原文件标签；是否允许写回由元数据设置决定。

“管理版本”用于：

- 查看同一 Release Track 的媒体版本与设备副本。
- 将错误分离的曲目关联到已有 Recording。
- 拆分错误关联。

### 9.2 专辑

在专辑详情点击“编辑专辑”。可维护发行资料、credits 和封面，并选择要批量传播给专辑歌曲的字段。

如果同一专辑因为年份缺失等原因被拆成两个条目，使用“迁移/合并专辑”：

1. 打开需要迁出的来源专辑。
2. 选择目标专辑。
3. 确认目标保留的标题、封面和发行资料。
4. 执行后检查曲目、光盘号和曲序。

### 9.3 艺术家与艺术照

在艺术家详情点击编辑：

1. 维护姓名、简介、标识和外部链接。
2. 在“艺术照”添加本地图片。
3. 为图片选择头像、横幅、背景或组合成员等类型。
4. 添加最多五个裁剪区域，拖动裁剪框和边缘手柄。
5. 在“显示效果”中为不同位置选择图片和布局。

裁剪手柄改变选区，不应拉伸原图。区域列表提供移除按钮。

## 10. 歌词编辑

在歌曲编辑器进入歌词区域：

- 粘贴纯文本或 LRC。
- 使用播放位置为每行设置时间。
- 对支持的数据进一步编辑逐字时间。
- 添加翻译、注音和演唱者。
- 预览当前行高亮和自动滚动。

保存前处理重叠时间和无效时间标签。普通 LRC 没有逐字数据时，播放器仍以逐行方式正常显示。

## 11. 资料库管理

### 11.1 设备与来源

“设备与来源”显示每台设备的文件数、可用数、问题数和容量。

- **停用**：暂时不让来源参与可用性和播放选择，保留记录。
- **恢复**：重新启用已停用来源。
- **删除来源**：移除该来源及相关目录记录，不删除远端设备上的物理文件。
- **删除设备**：清理重复安装或已经废弃的设备身份及其来源记录。

只有确定设备不会再使用时才执行永久删除。

### 11.2 物理删除文件

在文件系统中删除音乐后，下一次完整同步会把副本标为缺失。资料库仍可能保留歌曲身份，因为：

- 其他设备还有副本。
- 用户资料、歌单或历史仍引用该歌曲。
- 缺失记录尚未被明确清理。

这是正常的可恢复设计。需要永久移除时在资料库管理中筛选缺失文件并执行相应清理操作。

### 11.3 重复歌曲

使用“查找完全重复歌曲”生成候选。系统会保守比较标题、艺术家、专辑、版本、年份、光盘/曲序、录音类型和时长。

合并前检查：

- 两项是否真的是同一次发行中的同一曲目。
- Live、翻唱、重录和剪辑版是否被错误混入。
- 专辑、年份和曲序是否只是缺失或错误标签。

不同专辑收录的同一 Recording 不应直接删除其中一项；应使用 Recording 关联，让每张专辑仍保留自己的曲目。

## 12. 分发音乐到设备

1. 从歌曲、专辑、艺术家或歌单选择“分发到设备”。
2. 选择目标 Client。
3. 选择原始质量、FLAC 或 AAC profile。
4. 确认目标来源和预计任务数量。
5. 在分发任务中查看上传、转码、下载和校验进度。

目标 Client 必须至少配置一个可写音乐文件夹。Android 目标必须仍持有目录授权。完成后执行本地扫描，文件才会出现在统一资料库中。

分发失败时重点检查日志中的：

- 源副本是否在线可读。
- Core 是否有足够临时空间。
- FFmpeg/ffprobe 是否可用。
- 目标目录是否可写。
- 文件大小与 quick hash 是否一致。

## 13. 离线与弱网使用

### 13.1 状态变化

Client 会区分健康、缓慢、重连、离线和重新同步。网络变慢时：

- 已知页面继续从本地投影打开。
- 播放控制使用短超时，不无限等待 Core。
- 本机副本优先播放。
- 当前队列和模式不会因为断线被清空。

### 13.2 离线可用性

歌曲行上的标签表示当前状态：

- **此设备**：当前 Client 有可访问副本，可以离线播放。
- **Core 本机**：只能由 Core 或在线流播放。
- **设备名**：副本位于另一 Client。
- **不可用**：当前没有可访问路径。
- **检查中**：正在确认来源状态，不代表文件一定丢失。

详情中显示“可用”但离线播放仍失败时，通常是本地文件映射的 track ID 已过期、目录授权失效或文件已移动。重新同步本地来源可刷新绑定。

### 13.3 重连

恢复连接后 Client 在后台：

1. 校验 Core 身份与 catalog epoch。
2. 上传离线 outbox。
3. 获取缺失的目录和播放事件。
4. 刷新图片及详情缓存。
5. 保持前台页面和正在播放会话不被重置。

## 14. 日志与故障排查

在“设置 → 日志”打开详细日志后复现问题，再导出 JSONL。日志可能包含本地路径和网络地址，分享前请检查隐私信息。

### 14.1 点击播放或切歌很慢

查看以下事件的时间差：

- 用户控制命令创建。
- 本地副本解析。
- Core 请求开始/超时。
- renderer 命令接收。
- 媒体打开与首帧播放。

若本机已有副本却仍等待长时间，检查本地 binding 是否对应当前 track ID，以及控制通道是否错误地阻塞了本地媒体选择。

### 14.2 Android 文件夹不可用

- 从系统选择器重新添加目录，不手填路径。
- 确认宿主没有撤销持久 URI 权限。
- 在系统设置中重新授予音乐/文件权限。
- HarmonyOS 兼容环境中尝试选择兼容层实际暴露的目录。
- 导出日志，查找 `Folder unavailable`、`Illegal argument in isolate message` 或 manifest HTTP 错误。

### 14.3 Android 同步 HTTP 500/422

这通常表示某个 manifest 字段无法解析，或 Core 在对账时违反数据库约束。日志中应保留 Core 返回的完整错误和当前批次范围。不要反复卸载 Client；先保存日志并检查异常文件元数据、设备 ID、来源 ID 和 scan ID。

### 14.4 Windows Core 无法启动

检查：

```powershell
Get-Service IntMusicCore
sc.exe qc IntMusicCore
Get-Content C:\ProgramData\IntMusic\Core\service.log -Tail 200
```

若日志显示数据库 migration 已被修改，不要删除数据库来掩盖问题；应使用与数据库 migration 历史兼容的 Core，或从备份恢复。

### 14.5 部分音频出现杂音

记录文件格式、声道数、采样率和播放路径。多声道文件应经过正确的声道布局/下混处理；若只有 Core 流播放有问题而本机播放正常，同时检查转码 profile、输出设备格式和 renderer 解码器。

## 15. 更新与卸载

### 15.1 更新

- 先备份 Core 数据库。
- 使用相同签名的 Android APK 覆盖安装。
- Windows 直接运行新安装器，由安装器停止 Client 和服务。
- macOS 使用同一签名渠道的新版 App 替换旧版。
- 更新 Core 与 Client 后等待一次完整后台同步。

当 Core 与 Client 协议同时变化时，建议先更新 Core，再更新 Client；迁移期接口会尽量保持兼容，但新功能可能要求两端都是新版本。

### 15.2 卸载

卸载 Client 不会自动删除 Core 中的设备记录。确认不再使用后，在“资料库管理 → 设备与来源”永久移除旧设备。

卸载 Core 前务必备份数据库。删除 Core 数据目录会失去收藏、编辑资料、合并关系、歌单、历史和设备绑定，但不会删除位于其他目录的原始音乐文件。

## 16. 开发模式常用命令

Windows：

```powershell
.\scripts\dev-shell.ps1
.\scripts\check-env.ps1
.\scripts\run-core.ps1

cd apps\client-flutter
flutter run -d windows
flutter build apk --debug
```

macOS/Linux：

```bash
cargo run -p core-cli -- serve

cd apps/client-flutter
flutter run -d macos   # 或 linux
```

Core CLI：

```bash
cargo run -p core-cli -- status
cargo run -p core-cli -- diagnostics
cargo run -p core-cli -- library list
cargo run -p core-cli -- library add /path/to/music
cargo run -p core-cli -- scan start
cargo run -p core-cli -- outputs list
cargo run -p core-cli -- db backup /path/to/library-backup.sqlite3
```
